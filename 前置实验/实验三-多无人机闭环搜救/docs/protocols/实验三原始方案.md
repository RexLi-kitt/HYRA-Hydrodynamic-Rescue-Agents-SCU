# 实验三：1k–5k格地图下的多无人机闭环搜救

## 1. 要验证什么

核心问题是：**在未知目标、局部观测和持续变化的洪水中，残差的物理联系与时间有效性，能否帮助多无人机及时调整行动，并比强历史基线完成更多任务？**

实验三承接前两项实验，把“预测改善→窗口判断→任务分配→实际完成”接成闭环。采用你确定的路线：**2500格主实验，约1000和5000格扩展；集中式滚动规划；可控合成洪涝场景。**

主要判断依据是实际完成服务的增量，预测误差和探索覆盖用于解释增益来自哪里。

## 2. 地图、机群与时间尺度

固定每格 **10×10米**，通过扩大实际范围增加格数。

| 条件 | 地图 | 实际范围 | 无人机 | 隐藏目标 | 每机载荷 |
|---|---|---|---:|---:|---:|
| 小规模 | 32×32＝1024格 | 320×320米 | 4架 | 12个 | 4份 |
| **主实验** | **50×50＝2500格** | **500×500米** | **10架** | **30个** | **4份** |
| 大规模 | 70×70＝4900格 | 700×700米 | 20架 | 60个 | 4份 |

这样各档均为每机约250格、3个目标，载荷与目标之比保持一致。三个尺度的表现反映系统随面积和机群扩展的能力。

共同设定：

- 每回合1200秒，飞行速度5米/秒，感知窗口5×5格，每5秒采样；途中采样使用当时实际位置。
- 每10秒滚动规划；发现目标、服务失败时立即更新计划。斜向飞行按实际距离计时。
- 完整服务12秒，整个服务区间水深均不超过0.8米才算成功；失败消耗时间，成功消耗一份载荷。
- 主条件为2厘米观测噪声、零延迟；2500格另测10秒延迟。
- 起点按空间分层布置；目标从可达位置随机生成，生成过程不参考真实服务窗口或方法表现。未发现目标也计入完成率分母。

洪水继续使用ANUGA。任务格与水动力计算网格分别设置，后者按米制精度加密核验；ANUGA本身采用三角形计算网格。[官方说明](https://anuga.readthedocs.io/en/stable/background.html)

水情采用**有限涨水过程**：120秒起涨，总增幅0.6／0.9米、涨水历时600／900秒，四种组合全部保留，涨水结束后保持。名义预测低估增幅25%；叠加幅度0／0.1／0.2米的局地边界扰动。上述条件先做独立设计集检查，再冻结，避免沿用旧线性涨水导致后半程普遍无法服务。

## 3. 比较哪些方法，如何形成闭环

五组使用同一个预测骨干、相同合法历史、训练样本、输入容量和规划器，只改变信息组织方式。

| 组别 | 信息处理方式 | 回答的问题 |
|---|---|---|
| H：强历史基线 | 完整原始观测、历史预测、位置、年龄与缺失标记 | 普通历史学习能做到什么程度？ |
| E：统计联系 | H＋训练数据学习的稀疏区域联系 | 单靠统计联系是否足够？ |
| **P：HyRA** | H＋物理候选约束、经训练验证的联系和时间衰减 | 物理组织是否带来额外收益？ |
| P错联系 | 保持联系数量和模型容量，预先置换联系并重新训练 | 收益是否依赖联系对象正确？ |
| P均匀时间权重 | 保留时滞对齐、历史长度和过期规则，取消显式衰减 | 显式时间衰减是否有用？ |

**2500格运行全部五组；1024和4900格运行H、E、P。** H与E中较强者只按验证集选择一次，冻结为主要比较对象B*。

闭环执行规则：

1. 无人机搜索未知区域，发现目标后共享位置与任务状态。
2. 信息模块输出目标未来水深曲线及完整12秒可服务窗口。
3. 中央规划器安排已知任务的访问顺序与执行机，空闲机分配到探索前沿；统一优先增加可完成任务，其次增加覆盖、减少飞行。
4. 每次只执行当前计划的前10秒，再根据新证据更新；规划超时则继续仍可行的已有计划，失去可行计划的无人机等待重规划。

统一输出接口为 `WindowEstimate`：查询位置、预测发布版本、未来水深曲线、可服务区间及证据支持标记。超过已发布预测有效期的区间返回未知。

闭环中各组可能走出不同路线，因此控制相同的传感、通信和行动权限；另外设置**固定路线、相同记录回放**，隔离信息模块本身的贡献。发现目标后的合法本地水情也正常使用。

## 4. 数据、实施顺序与验证

采用全新的家族划分：**6个设计家族、24个训练家族、12个验证家族、36个测试家族**。同一家族的全部尺度、扰动和布局留在同一划分中。

- 三尺度混合训练，共享同一个可变规模模型；端点实验检验可扩展性。
- 所有方法使用共同采集的训练记录；新场景的联系由冻结构图规则结合公开地形和独立名义模拟生成。
- 每个测试家族使用2套目标布局与观测噪声配置、3个模型训练种子，方法之间成对比较。
- 主测试共2376回合；2500格10秒延迟扩展648回合，**合计3024回合**，不含开发与回放。

按以下顺序实施：

1. **环境与算力预检**：测4900格、20机的积分时间、内存、存储和规划耗时；将现有稠密地图运算改为稀疏计算，移除固定4机、300秒和100格的限制。
2. **物理与时钟核验**：比较空间加密及1／2秒输出，检查服务窗口标签；核对连续飞行、完整服务、预测版本和观测到达时间。
3. **2500格开发**：完成五组训练、固定记录回放和验证集选模，冻结全部设置。
4. **独立测试**：一次运行三个尺度及延迟扩展，保留全部失败、空机会和负收益场景。

前置检查依据是数值稳定、几何可达、输入合法和评分正确。设计集同时报告窗口分布及可挽回空间，场景不按HyRA收益筛选。

## 5. 指标、判定与交付

**主要指标**为全部隐藏目标中的成功服务率，以及P相对B*的配对增量，单位为百分点。

同时报告：

- 未发现、发现太晚、窗口误判、执行失败、资源或时间耗尽的目标数量。
- 固定记录下的预测误差、完整窗口错误率。
- 新证据引发的改派次数，以及改派后实际多完成或少完成的服务。
- 探索覆盖、重复搜索、飞行距离、规划延迟和峰值内存。

统计先在家族内平均布局，再按家族和训练种子成对重采样，给出95%区间；格子、时间点和布局不计作独立家族。

主要判定为P相对B*的增量区间下界大于0；**增加3个百分点**设为工程目标，单独报告是否达到。若仅优于错联系或时间消融，则结论限定到对应机制；若收益方向随数值加密改变，先处理数值问题。

最终形成独立实验三代码包、冻结配置、原始统计和一份报告。报告按“研究问题→实验设计→执行方法→结果→结论”组织，重点解释：**多完成了多少任务、信息在哪一步改变了行动、在哪些条件下无效。**
