# V2 动态洪水投放与冻结模型验证

本快照在 V1 六算法研究基础上归档动态落水、搁浅后再次漂移，以及 **GRU区域需求预测＋观测水流前推＋完整覆盖规划**。不替换生产默认，不合并PR，不把合成任务成功率解释为真实洪水救援可靠率。

## 先看结果

24个独立生成的新水动力父场，各2套新人员布局，共48场，每场40人。冻结后新增180次评估（主测试144次、方向压力36次），**新增训练0轮**。既有GRU快照来自32轮监督训练。

|方法|人数完成|人数完成率|全40人场景|至少38人场景|
|---|---:|---:|---:|---:|
|完整覆盖规划|1508/1920|78.54%|0/48|0/48|
|观测水流辅助规划|1488/1920|77.50%|0/48|0/48|
|GRU融合规划|1751/1920|91.20%|5/48|21/48|

“完成”指个人截止前连续投放物资10秒，不代表人员转移或现实获救。主模型人数完成率95%父场bootstrap区间88.80%–93.28%。相对较强规划，人数+12.66个百分点、至少95%人数完成场景+43.75个百分点；全员场景仅+10.42个百分点，不能写成所有指标都领先15个百分点。

**保留的失败和未验证项：**旋转90°时GRU人数204/240（85%），至少38人场景0/6，方向目标失败；X镜像223/240（92.92%）、至少38人2/6，但场景差区间下界为0。合并方向平均不能掩盖旋转失败。所有180次评估实际再漂移事件为0；规则启用不代表该机制被这批表现验证。主场被接受的1920次首次落水全由随机机制触发。

## 参数与方法

1km正方形合成区域，100×100水场格；40人、4架无人机、总时长1500秒、个人180秒期限；60米圆形视野、10米/秒飞行、1秒观察和决策、10米投放半径、10秒连续投放、5米机间间隔。主测试不启用局部雾。三个方法共享人员、期限、环境和观测机会，规划器未刻意削弱。coverage100是历史标签，实际视野由配置决定。

搁浅后重新有水：水深≥2米或流速模长≥1米/秒强制恢复漂移，否则按5%/分钟转换的逐秒概率触发；干地不触发，障碍挂靠状态仍停止，首次落水的个人截止时间不刷新。2米/1米每秒是本实验规则，不是人体安全标准。

GRU输入为每100米区域14个公开特征、4帧30秒历史；隐藏维度32，Softplus输出区域未发现待救助人数。真实人数仅作为TRAIN监督标签。覆盖/学习需求各半，当前/60秒观测流速前推各半；未知或超过120秒的流速不用于前推。冻结权重与归一化参数一起存于 `model/gru-32.pt`，SHA256为 `6d9338befc35bfc1ea130d9702ee1a2707317554a81b7681542d47ff1edcf143`。

## 证据限制与后续

新父场不与原训练索引重叠，但仍属同一合成生成族；只评估一个训练种子。0/120/480秒隐藏状态篡改审计通过，说明被测决策路径未观察到直接真值泄漏，不是所有可能偏差均被排除。内部有限非负与水量审计通过不等于实洪验证。
