# 已训练策略的交互控制台

无人机工作台现在支持单机 R0/R1/R2、固定序列、双机 R0/R1/R2，以及 QMIX、Sur-QMIX、Sur-QMIX+Data、Sur-QMIX+Physics 四类已训练双机策略。每类模型可选择固定实验种子 11、29、47。

## 启动和使用

桌面“HyRA 无人机工作台”或 `启动工作台.ps1` 启动新版入口 `console_app.py --port 8767`。打开 <http://127.0.0.1:8767/>，在“行动方式”中选择模型，再点击“生成观测回放”。原 `run.py serve` 保留旧版单机页面；科研复现入口不变。

网页进程需要 NumPy；推理子进程使用现有 `D:/Scripts/python.exe` 及其 PyTorch 环境。其他机器可以通过 `HYRA_LEARNING_PYTHON` 指定学习环境解释器。不自动下载模型，不启动训练。

选择训练模型时，固定使用原协议的 32×32 网格、5 米格距、600 秒任务、5 秒实际观测、10 秒动作及两机固定起点，其余飞行参数也按冻结配置锁定。不兼容的洪水过程会提示并禁用模型运行。除原演示和导入过程外，也可选择已有的 21 个研究过程；交互运行不能算新增独立实验或据此重新选择模型。

## 模型和回放

使用 `generated/sciml-round1/model-freeze.json` 登记的选定检查点对应的 actor-only 导出文件。执行前验证导出摘要、选定模型摘要和 35 份冻结科学源码摘要；不匹配时明确失败。每次保存结果中的 `execution` 都包含方法、种子、actor SHA256、父检查点 SHA256、选定回合和 CPU 执行设备。

模型根据当前合法观测、机位、静态地形、前一动作与循环状态产生动作；不向策略传入隐藏水深或未来标签，也不加载训练用的世界模型、mixer 或优化器。页面的真实水情用于离线检查，认知地图仅由实际观测更新。模型失败不会回退为规则。

双机回放显示两条不同颜色的轨迹、共享认知地图、全队航程和转向时间、碰撞计数。正常一轮为 60 次联合决策、121 个观测时刻、242 条单机观测。动作日志每个时刻保存两架无人机各自的行动。结果存储于 `generated/web/<run_id>/`，推理请求和诊断位于 `generated/console-jobs/`。

目前的模型是已训练实验模型，正式留出评价尚未超过规则基线；接入控制台不改变原实验结论。

## 验证

四类模型种子 11、物理辅助模型种子 47、双机 R2 已通过真实推理和独立的动作几何、观测合并、记忆地图、变化发现及指标重建核查。单机 R2、固定悬停序列和研究过程上的单机 R1 通过回归检查。非法种子、改变冻结配置、错误网格和未知方法均被拒绝；禁止访问 CTDE 隐藏真值后模型仍可运行。35 份冻结科学源码保持原摘要。浏览器验证了 QMIX、物理辅助模型、种子切换与双机逐帧回放。

改动只位于独立的 `console_app.py`、`console_model_runner.py`、`console-static/`、启动配置和本文档，未修改原算法或训练源码。
