# 无人机双模型组合实测（2026-11-01）

原A/B/C只是六种算法的对照分组，每种分别训练。用户本轮明确要求尝试实际组合且不限制原分组。本轮将两个已训练策略用于同一4机集群，各负责2架，确实重新运行联合轨迹，未用两个单模型分数的算术平均代替组合结果。

## 固定方案与口径

- 五个单模型检查点作对照，四个组合，各两种对角分配。单模型16次，组合32次，共208次重放。每个场景两种分工等权保留，不事后挑选。
- 所有对照与组合统一使用自动施救、重试控制、随机动作执行。无覆盖补漏接管，水情、奖励、观测权限、最长300步和任务终止规则均不变。
- 仅复用已有权重，新增训练回合0，优化更新0。训练预算不同的检查点组合是可行性试验，不是同预算算法排名。
- 2个合成父水场×4布局×2动作随机种子。重放数不代表独立洪水数，开发验证已经被反复使用；未访问封存50场独立测试。

## 改动、原因与回归

- 基线：priority_train.py 的 rollout、ServiceCommitment 和 RetryGuard 保持原样。新增 combo_eval.py / MixedFleet.act 仅根据预登记的机号分配选择策略。默认训练入口及已选保留版本没有变。
- MAT是因果联合动作解码器，不能将两个完整动作向量直接拼接后忽略上下文。新执行器按机号逐个生成动作，让MAT只读取本步已经确定的真实混合前缀；仍然一次同步执行所有飞机动作，没有中途观测。
- 所有方法控制单机时使用该机原有actor或MAT对应位置，保持原机号。角色固定为两种对角分配，不把“更适合搜寻/救援”当作已证明的专长。
- 回归：5个专家的同专家包装对随机/固定动作均与原act一致；所有组合通过强制施救掩码检查；MAT读取最终混合动作前缀检查通过；运行结束全部模型参数哈希不变。
- 预登记候选条件同时限制获救比例不降、覆盖容差、潜在冲突≤0.02、动作种子与分工稳定性，并要求最低可分辨收益。任何未满足条件都保留，不删失败组合。
- 回退：使用原单模型入口或已保留HASAC256/HATRPO512。此次没有覆盖权重，未推送或更新PR。

## 局限与下一步

- 两个分别训练的策略此前未对新队友联合适配。直接混用无收益不等于所有层级或联合训练方案都无效。
- 下一轮若继续组合，应一次只改变协作机制，固定数据与评估，不把增加训练轮数当作必然改善。若直接组合未优于单模型，先保留单模型对照，不能宣称组合改进成功。
- 人员“获救”是合成环境中的连续悬停服务代理指标，未验证真实吊运、建筑、续航或天气约束。
- 本次壁钟耗时3.01分钟。新增训练0轮；原主线总训练3072轮不变。
