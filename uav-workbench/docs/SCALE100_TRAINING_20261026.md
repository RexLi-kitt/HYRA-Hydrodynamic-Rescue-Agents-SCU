# 100米双任务、六组训练执行记录

用户在地图尺度测算后确认“就按照这样展开训练”。本版本按100×100米、900秒任务推进，保留八方向、双层GMRF、Sur-QMIX、探索/探索搜救及科学机器学习比较。旧四动作研究与八动作12回合模型均不修改、不作为新训练结果。

## 固定环境契约

- 原始20×20网格，dx=5米，2机；另验证4机接口。每5秒移动一个相邻格，直向1米/秒、斜向√2米/秒，尚未实现恒定物理速度。
- 方形5×5格传感窗口，可靠共享已到达记录。基础9通道外，增加局部/池化水深、u、v、有效掩码、实际记录年龄共10通道，以及公开静态底床局部/池化2通道，总计21通道。旧9通道权重不混用。
- E1无人员、无源信号、无施救及其超时惩罚；持续到900秒，用于动态探索和复查。E2五个人员目标，发现、接近、连续10秒施救，水深/流速影响服务是否能继续。
- E2水深0.08米、流速0.3米/秒是合成服务条件，不是人员生存或真实飞行安全阈值；未来需敏感性实验。无人机飞过淹水区域本身不受限。训练/开发60个人员位置中4个存在随水情变化的服务机会，动态条件较稀疏，需继续诊断；不因此宣称物理知识已有任务收益。
- 共同奖励：新探索格数×0.1，纠正陈旧错误记录格数×0.15，无效动作/碰撞×-0.2；E2额外每次施救+5、截止未施救人数×-2。新奖励属于洪水扩展任务，不能称为原论文逐项复现。
- 主要报告E1首次覆盖及动态地图质量，E2施救比例及覆盖。沿用的`correct_coverage`是干/湿类别分别计算后平均的均衡正确覆盖，不是全图正确像素数/总像素；需要与首次覆盖分开解释。

## 数据与独立性

洪水端`generate_scale100.py`调用既有原始SWE求解器，不重复末帧或插值充当真实数据。每个场景有0到900秒每5秒的181帧，并保存每帧之后一个真实接受的内部短步(h,hu,hv)、dt、源项及底床。

数据在洪水端`generated/scale100-900s-20261026/`：fit-101/211/307，development-401，holdout-503/601。母地形、来水参数独立采样；这是同一程序生成器下的独立合成父场景，不能外推为多个独立真实灾害。训练种子/人员种子不计作独立地形。

开发评价只读取development-401；正式冻结前不进行留出策略评分。已有数据清单包含水深、流速等完整性摘要，不能将元数据检查冒称留出性能确认。

## 六组对照

| 组别 | 结构编码 | 协同算法 | 辅助损失 |
|---|---|---|---|
| B0 | 同源原始记录 | QMIX | 无 |
| B1 | 双层GMRF | QMIX | 无 |
| B2 | 同源原始记录 | Sur-QMIX | 无 |
| B3 | 双层GMRF | Sur-QMIX | 无 |
| D | 双层GMRF | Sur-QMIX | 当前/短步水情数据监督 |
| P | 双层GMRF | Sur-QMIX | 同D + SWE内部短步一致性 |

六组网络都分配同样的辅助头参数；D/P使用相同输入、头、标签、训练步和初始化种子。差异限P增加物理项。辅助头读取合法历史GRU编码和公开底床，训练标签才含当前/未来真值，预测不写入实际认知地图。

Sur机制复用已登记的梯度maxQ范数、批内归一化、固定单位方向、停止梯度幅值；训练时增强、执行和目标计算使用干净分支。CNN/GRU和可靠通信等仍与原论文存在适配差异。QMIX集中混合器可用真值状态，actor不能读取它。

物理算子复用未改动的`hyra_learning/physics.py`：closed/Rusanov/MUSCL/RK2、Manning0.035及体积源项。不能用于未验证的开放边界等配置。初始开发权重Data=0.05、Physics=0.05、归一化(h,hu,hv)=(0.5,0.25,0.25)；这些属于开发设置，正式确认前还需审阅学习曲线与稳定性并冻结。
