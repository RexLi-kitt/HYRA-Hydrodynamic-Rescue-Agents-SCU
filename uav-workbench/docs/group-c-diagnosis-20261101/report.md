# C组256回合退化诊断（2026-11-01）

本次回答“C组为什么退步这么大”。复用64/256回合检查点，完成64场不更新参数的诊断回放。保留原固定动作验证结果，不以新的随机采样结果覆盖原评分；没有追加训练、修改奖励、任务门槛、地图、服务控制器或洪水模型。

## 已确认的行为原因

|算法|原64固定动作：覆盖/施救|256固定动作：覆盖/施救|256随机采样诊断，两种子范围：覆盖/施救|
|---|---|---|---|
|MAT|73.6875% / 68.75%|62.1175% / 58.75%|88.74125%—91.68625% / 87.5%—90%|
|COMA|85.9275% / 88.75%|3.7475% / 1.25%|78.8825%—78.965% / 71.875%—72.5%|

这里的施救比例是获救人员数/20；不是整场任务完成率。所有本次回放均未达到全图覆盖且全部施救的整场成功条件。自动施救开启，覆盖补漏规划关闭。

**MAT：固定选最高概率动作引发反复避碰和停滞。** 原64固定验证没有潜在冲突；256在8场共出现1622次潜在冲突对计数，环境安全层阻止相应移动，并非1622次实际撞机。6场最后100步没有新增覆盖格；其中4场最后100步每步都有一次潜在冲突。改成按同一策略概率抽样后，两种子对应计数分别降至11和13，覆盖恢复约89%—92%，施救约88%—90%。说明固定动作循环和训练/执行选动作方式差异对退化有实质影响，不能把它解释为网络完全失去搜索能力。多种子随机回放同时改变后续路径，不能由此推断每个损失百分点评分的唯一成因。

**COMA：训练中已经越来越偏向悬停，固定选最大概率进一步放大。** 额外训练最初32回合平均覆盖91.4425%，最后32回合降至63.176875%；施救从91.5625%降到60.625%。256固定验证的9592次自由决策中，悬停均为概率最高动作，并全部被选中；这些状态的平均悬停概率65.8406%，不是网络给出99.96%的悬停概率。含服务动作在内原统计9596/9600次实际选择悬停仍正确。随机采样允许偶尔移动，覆盖回到约79%、施救约72%，但沿采样轨迹的悬停概率仍约76.6%—76.9%。这说明确有策略退化，同时固定选最大值使退化看起来更极端。

**不是“发现人后强制停留”造成全部停飞。** 以上悬停概率与动作统计只在多于一个合法动作的自由决策中计算，服务强制动作单独计数；发现后接近/连续施救规则在64和256保持相同。

## 仍未确认的底层训练原因

- 两种方法均为本项目适配实现，不能把当前结果当作原论文算法必然失败。
- COMA训练后期critic损失降低，但任务指标下降；损失下降不能替代任务收益。避碰/边界惩罚、团队信用分配、探索强度和critic更新节奏是待区分因素，尚无单因素试验证明其中哪项是根因。
- 本次COMA最终critic对悬停相对策略加权基线的平均Q差为负（固定回放约-0.0644，随机约-0.0455）。所以不能仅凭悬停行为就声称“最终critic明确高估悬停”；需要记录训练过程中的逐动作优势和梯度。
- MAT本地训练未保存策略损失、价值损失、策略熵和更新幅度等过程诊断，不能事后确认是否为价值学习压过策略学习。训练随机覆盖最后32回合仍90.8672%，与固定验证明显不同。
- 每32回合覆盖latest.pt，未保留本次192段所有历史模型；原64和最终256仍在，不能声称可以直接恢复本次训练的192回合模型。

官方实现核对只用于提出检查方向，不作为性能证据：[COMA官方PyMARL learner](https://raw.githubusercontent.com/oxwhirl/pymarl/master/src/learners/coma_learner.py) 使用的优化器、critic更新节奏和目标网络更新方式与本地适配不同；[MAT官方trainer](https://raw.githubusercontent.com/PKU-MARL/Multi-Agent-Transformer/main/mat/algorithms/mat/mat_trainer.py) 支持价值归一化/价值裁剪并记录多种训练诊断。本地差异不自动等于错误，也未证明照搬后必定改善。
