# 洪水模拟第二轮修复与合理性论证

日期：2026-10-24。修改位于桌面 无人机大创/HYRA。没有替换浅水方程，没有调参拟合40点。

## 1. 已复现并修复：建筑内基流源导致丢水
旧行为：4×4平底干网格，封闭边界，先设[1,1]为建筑，再设该格1m³/s基流，推进1s。输入累计1m³，域内水量0m³，收支残差-1m³。原因是set_baseflow没有检查已存在的solid，末尾清零建筑水深。
修复：flood_solver.py:216/225 在提交新基流数组前拒绝正流量与建筑重叠；拒绝后保留原基流数组。
另修：flood_solver.py:113 对set_environment先完整验证并检查与基流重叠，再一次性更新。旧实现会先写入solid再抛错，调用方捕获异常后可能继续使用已损坏状态。
论证：建筑为不透水计算格，不能既把它作为体积源又清零水量。拒绝无效输入比把流量偷偷挪到邻格更透明；两种设置顺序都应满足同一约束。现有网页部分入口已有检查，本缺陷首先证明底层API存在漏洞，不证明既有Merewether场景触发了它。
3项新增测试通过：先建筑后水源；先水源后建筑；后续非法参数不应部分应用前面的合法设置。保留有效水源推进1s，域内水量为1m³且残差接近机器精度。

## 2. 保护性修复：粗化破坏干湿岸线初始水面
grid_coarsening.py:66 新增coarsen_water_state，检测混合干湿粗格中平均床面+平均水深与湿子格平均水面的偏差。
偏差超过1e-6m即拒绝这次粗化，提示使用原始格宽。该阈值是数值筛查容差，不是实测准确率标准。
flood_run.py:130接入生成初始水体路径；map_sessions.py:135接入原始尺寸的自定义初始水深路径。显式initial_depth存在时先跳过不会使用的生成水体初始化，再校验实际输入。
论证：原样例2m粗格产生0.696766m/s虚假流速而仍守恒；强制原水面会损失8/56水量。当前单床面单水深粗格无法普遍同时保留细格水面与蓄水量，因此先阻止已知不一致输入，不伪造一个“修复后”的粗网格解。
4项新增测试通过：岸线被拒绝、原格静水、全湿水面与体积保持、干地图通过；包含生成与用户输入路径的集成检查。
限制：此举会使部分原先可跑的2/4倍格宽场景报出明确提示；请选择原始格宽重新运行，计算成本可能上升。它不是子网格物理模型，也未解决已经以粗网格输入且缺少细格信息的场景；不保证所有粗化误差都被检测。自定义地形及后续障碍变化还需要额外校验。

## 4. 下一步与不能承诺的内容
仍需Merewether原始数据、分层脚本与评分文件，才能评价40点误差是否改善。该报告干地形、无基流；本轮两个物理触发场景均不能直接当作其误差根因。
后续优先验证斜墙和窄通道对齐敏感性、真实混合边界、摩阻与坡度平衡、流速观测口径。三维NS只用于有证据需要的局部验证。
“符合所有现实”不是有限模型可达到的验收目标。可检验目标应明确场景、观测量、误差区间和适用边界。本轮证明的是修复特定缺陷和阻止一种已知失真输入，不证明真实洪水全面准确。
