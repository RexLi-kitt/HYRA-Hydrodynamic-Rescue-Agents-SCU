# 真实洪水数据集：空间、时间与地图表示草案

状态：数据规范草案。已在[独立真实洪水数据工作台](../../flood-data-workbench/README.md)导入Harvey 2017单站连续水位与现代地形概览，验证第一版空间／时间接入。全域逐时淹没、历史地形和真实事件求解条件仍未齐备；本规范不改变现有洪水求解器、观测调度或模拟参数。

## 1. 一个事件包含什么

每个事件保留原始文件，并建立统一空间参考的地图和带时间戳的观测记录。静态地形、真实观测、模型预测分别保存；实际观测稀疏时不要求提供完整的“真实洪水四维场”。

- 静态：地面DEM、可用的障碍轮廓、投影坐标系、网格仿射变换、垂直基准、来源与有效区。
- 动态观测：淹没范围、水位站记录；若来源确实提供，再增加水深或流速。记录变量、观测位置／覆盖范围、原生分辨率、质量、误差或不确定性信息。
- 时间：观测起止时刻、数据可获得时刻、来源时间精度。历史回放只释放当前已经可获得的数据。
- 评估：事先指定校正用观测与留出验证观测；峰值及事件累计产品另作事后评价。

第一事件优先选择有DEM、连续水位记录、多时相淹没范围及清楚时间信息的资料。流速、全域水深不作为必须字段。只有洪痕或最大淹没图的事件，不适合作为完整动态校正数据集。

## 2. 空间离散

沿用现有规则矩阵 `[z,x]` 和米制单位；新事件使用适合本地区的投影坐标系，保留其CRS、原点和仿射变换，不能把经纬度角度直接当米。地图采用北向上的原点定义，z由北向南增加。

对左上外边界 `(E0,N0)`、格宽 `d`，格中心为：

```text
E = E0 + (column + 0.5) * d
N = N0 - (row + 0.5) * d
```

用地理栅格库的统一仿射变换处理栅格与点位，固定边界归属规则。局部裁剪沿用全域取格索引再减偏移，避免格边浮点误差改变测点位置。现有Merewether局部坐标不冒称地理投影。

预测网格维持既定格宽，观测保留原生空间支持。10米观测可以投影到1米显示网格，但不因此获得1米物理精度，也不能被当成100个独立实测值。评价时把模型结果映射到原生观测像素、轮廓或测点所代表的范围。

| 来源 | 地图表示 | 重采样／比较原则 |
|---|---|---|
| DEM | 浮点地面高程 | 保留垂直基准及有效区；墙／墩独立处理 |
| 淹没轮廓／分类栅格 | 淹没比例或湿／干／未知 | 多边形按面积相交；分类数据不作双线性类别混合；保留观测覆盖比例 |
| 水位站 | 点标记和时间曲线 | 保留测点，不扩散为全域水位；相对水尺需有基准才能转绝对高程 |
| 有效水深产品 | 水深栅格＋有效区 | 记录实测或估计身份；不跨陆地／建筑／缺测区任意插值 |
| 有效流速产品 | 速度大小／方向或分量＋有效区 | 有方向与坐标定义才转矢量；向北分量转工作台向下z分量时反号 |

对于局部覆盖的格子，分别记录“有效观测覆盖比例”和“有效区域内淹没比例”。覆盖外及云、阴影、遮挡、未判读区为未知，不是未淹。常年水体、本次洪水淹没、事件最大淹没范围的定义分别保存，比较模型时统一目标含义。

水面高程 `eta` 与地面高程 `bed` 只有在相同垂直基准、有效位置、相容空间支持下才能换算 `depth=max(eta-bed,0)`。一个水位站不能直接给全图设置相同水面。

## 3. 每种变量单独保留缺测和来源

建议每种空间变量包含 `values`、`valid_mask`、`coverage`、`source_resolution_m`、`support_type` 和质量信息；数据没给出不确定性时记为未知，不能把默认零写成真实测量误差。

```text
extent_fraction[z,x]      有效观测区域内的淹没比例，可选
extent_valid[z,x]         明确判读了湿／干的位置
depth_m[z,x]              水深，可选
depth_valid[z,x]          水深有效区
velocity_x_m_s[z,x]       流速分量，可选
velocity_z_m_s[z,x]       向地图下方的分量，可选
velocity_valid[z,x]       流速有效区
```

范围未知与水深未知的掩膜不能混用。只知道未淹并不等于提供了流速观测。数组可用NaN存缺测，掩膜为判据；不能把未知水深、未知速度填零。栅格缺测与已测得的零值必须在地图上可区分。

保留 `origin_kind=measured / remote_sensing_classification / estimated_from_dem / model_generated` 等来源身份。CEMS的部分水深产品由DEM和地理空间方法估计，并非直接测深；最大范围产品可能是多时相累计结果。[官方说明](https://mapping.emergency.copernicus.eu/news/the-copernicus-emergency-management-service-improves-flood-depth-monitoring/)

## 4. 时间离散

保留UTC绝对时间，同时定义事件原点 `t0_utc` 和相对秒数。观测按原始时间入库，允许不等间隔，不为了视觉连续而制造新观测。

每条记录至少保留：

```text
id, variable, observed_start_utc, observed_end_utc,
available_at_utc, time_kind, source_id, payload, quality
```

`time_kind`区分瞬时／一段时间的测量、截至某时刻的累计范围和事后峰值。洪痕是峰值约束，不能随意指定为某个时刻的实时水位。[USGS洪痕说明](https://www.usgs.gov/water-science-school/science/high-water-marks-and-flooding)

数据发布延迟必须保留；不知道真实发布时间时，采用显式标记的延迟假设，不宣称复现了真实数据送达速度。历史回放只有在 `available_at<=当前回放时间` 后才能向预测器提供该记录。

回放／评估时刻可以先采用60秒间隔作为候选，但不是强行认定数据每分钟采样。只有日级或小时级图像时，不能据此宣称具备分钟级全域验证能力。

示意：09:00和09:10各有一张淹没图，09:05时只能展示已获得的09:00图，并标注“观测距今5分钟”；不能用尚未获得的09:10图进行线性插值并交给预测器。若旧观测超过预设有效期限，应标为过时／未知，不能无限视为当前真值。若09:00图09:08才发布，09:05也不能使用它。

预测的当前起点、预报有效时刻、结果生成／发布时间另行保存，便于残差匹配与时延分析。用于预测的未来来水／降雨也遵守可获得时间，不能直接读取事后完整真实过程。

## 5. 与现有地图和回放对接

现有 `raster_import.py` 可复用米制浮点地形和独立障碍导入；它目前不执行地理投影转换。现有 `maps-playback.mjs` 接受不等间隔帧，但 `blendFrames()` 使用前后两帧插值，仅适用于已计算的预测显示，不能直接作为因果观测回放。

现有模拟过程固定保存 `[depth,u,v,maximum_depth]`。观测接口应独立采用“可选变量＋各自有效掩膜”，不伪装成完整模拟帧，也不附造步数、守恒账本或全域观测最大水深。没有观测流速时，观测页不显示流速箭头或用0表示静水。

工作台第一版展示建议：

- 地面和障碍使用现有地图。
- 观测淹没范围：蓝色表示观测淹没，浅色表示明确未淹，灰／斜纹表示未知或过时；水深与流速仅在有有效数据时显示。
- 水位站显示点位、最近观测值、测量时刻和观测曲线。
- 模型预测保持现有水深、流向和未来时间轴，与观测分层或并排查看。
- 残差只在变量、时刻、空间支持一致的有效位置计算。淹没范围使用漏报／误报图，不能把它与水深直接相减。
- 明确标注“观测”“推算产品”“模型预测”和“显示插值”。整张观测图的空白不自动由模型补成观测。

第一版仍固定观测范围／站点和既有计算方式，不加入自适应侦察、调度或校正算法。

## 6. 建议目录

```text
event-id/
  manifest.json             事件、CRS、地形网格、时间原点、来源与许可
  terrain/                  原始DEM、地面、障碍及有效区
  observations/index.jsonl  原始观测时间、可获得时间、变量与数据路径
  observations/gauges.csv   点位／水位及质量、时间信息
  observations/extent/      原生淹没轮廓或分类栅格
  observations/depth/       来源提供时才存在
  observations/velocity/    来源提供时才存在
  evaluation/split.json     校正与留出验证记录的划分
  derived/map-cache/        可重建的显示栅格，不覆盖原始资料
```

真实原始文件优先保留GeoTIFF、NetCDF、GeoPackage、CSV等来源格式。显示缓存才转换为工作台二进制矩阵，避免把重复的显示像素误当新增观测。先完成单事件数据身份、空间／垂直／时间一致性检查和回放，再扩大事件数量。
