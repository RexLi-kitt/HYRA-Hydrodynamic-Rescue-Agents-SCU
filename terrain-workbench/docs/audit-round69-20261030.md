## 二、更改原因、证据与取舍

用户要求定性而不要求逐点定量，因此必须检查会改变“涨还是退”等判断的错误，不能只说曲线外形相近。本轮首先登记protocol.json与输入哈希，然后复用已有全长结果，避免同配置长跑。[NOAA实验说明](https://nctr.pmel.noaa.gov/benchmark/Laboratory/Laboratory_MonaiValley/)确认这是1:400缩尺实验、水槽5.448×3.402m及三站位置；本轮数据是实验室证据，不是城市真实洪灾。官方与镜像逐项一致的既有证据见round50。

### 可复现步骤与固定规则

1. 用旧科学环境执行 `python -X utf8 -B flood-platform/benchmarks/compare_okushiri_qualitative.py --protocol <outputs>/round69/protocol.json --base <outputs> --output <新的审计目录>`。按哈希校验原始3992条观测，0–22.5秒共同窗451×3逐时刻相同；单位按原cm转m，不移时/去偏置。
2. 固定1s窗（末段22–22.5s保留）中首尾1/4分别取范围A、B，以 `[min(B)-max(A), max(B)-min(A)]` 判净趋势。整体高于记录舍入带为涨、整体低于负舍入带为退，重叠为无法判断；双方未知仍不是通过。1s为预登记的粗化诊断尺度，非有外部认证的救援时间精度指标。记录分辨率0.001cm不是仪器不确定性，不能假设已包含实验误差。
3. 全局主峰取记录半个舍入单位内所有候选并加半个采样步的时间支撑区间；区间不重叠才给先后。主峰先后不是到达时间。0.5/2s敏感性预先固定，均保存全行，未选择最好尺度。
4. 重建离线界面用README命令；新来源、反向区段或峰序变化时builder拒绝沿用旧问题文案。

观测主峰先后站3→站2→站1，模型站2→站3→站1；站2/3颠倒在三组均存在。原时间固定，不整体移时。区段内部先涨后退已记录，当前类别是净趋势而非整段单调。
