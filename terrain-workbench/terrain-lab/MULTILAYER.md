# 多层地图模型

在本地服务中打开 `maps.html`，或从地形／洪水页面进入“多层地图与观测”。这里实现 PPT 的地图与观测数据结构，继续使用已有的完整二维浅水求解器。所有层共享计算网格 `[nz,nx]`、原点、间距和模拟时钟；数组第二维为 X，第一维为 Z，`qy/wall_y` 的正方向为 +Z。

## 地图组与更新责任

| 地图组 | 数组／记录 | 更新者 |
| --- | --- | --- |
| `M_base` 固定环境 | 米制高程 `z`、逐格糙率 `n`、建筑 `solid`、飞行许可 `flight_allowed`、水源 `source_id`、排水能力 `drain_capacity`、`wall_x/wall_y` | 场景配置；本轮固定 |
| `M_ref` 环境真值 | 地表类型、建筑、人员类别、可选信号场 | 场景配置，仅调试／评价使用 |
| `M_water` 水情真值 | 水深、储水体积、X/Z 速度、公共边流量、累计收支 | 洪水求解器 |
| 每架无人机的 `M_obs` | 最近有效水深、速度、有效标记、采集时间 | 局部观测或收到较新的共享记录 |
| `M_exp` 探索与估计 | 曾探索、曾搜索有人／无人、已知或导入的地形场与信号场、已见人员、原有通道 | 有效搜索；历史标记不回退 |
| `M_pos` 位置 | 团队无人机的位置和已发现人员的位置、类别与采集时间 | 移动与有效搜索 |
| 信息年龄 | 当前模拟时间减 `t_water`；未知保持未知 | 显示时计算，不改观测值 |

人员和水体独立保存，同一个格子可以既有人员又有水。人员类别为 0 无人、1 未施救、2 已施救。每架无人机各有自己的已知地图，另有团队共享地图。共享不自动发生；可共享给团队或另一架无人机。建筑、禁飞、排水等均独立于人员类别和水深。

未知水深在 JSON 中为 `null`，在 NPZ 中为 NaN，并有单独有效掩码。确认干燥的观测为 `0` 且有效。无效观测保留旧记录；建筑格可观察其固定障碍标记，但其水面与人员不可见。当前观测器是圆形视野，无噪声、无延迟，不模拟三维遮挡。信息年龄表示记录新旧，不表示水深误差或置信度。

## 固定层参与洪水计算

- `solid` 是不透水格，水深为零，其边界采用反射压力条件。雨量只计入非固体格，未模拟屋顶雨水转排。
- `wall_x` 尺寸 `[nz,nx+1]`，`wall_y` 尺寸 `[nz+1,nx]`。墙面交换流量为零，但保留流体侧压力，静水不会因墙面产生假流动。
- `n` 是逐格 Manning 糙率。`drain_capacity` 是每格 m³/s 排水上限，扣除量受本步实际可用水量限制，并独立计入收支。
- `source_id=-1` 表示无水源。其他编号关联 `hydrographs`，每条过程为递增的 `[模拟秒, 总流量m³/s]` 序列，采用分段常数。一个编号覆盖多格时平分指定总流量。求解器按事件时间切分时间步，不会越过变化时刻误用旧流量。
- 公共边流量 `qx/qy` 的单位为 m²/s，表示最近计算子步实际使用的输水通量。两侧格使用同一份流量；它们不是简单用最终格心速度平均得到的值。
- 禁飞规则影响无人机移动。移动检查整条线段穿过的格子，包括触及网格角点的两侧格，不允许跳过禁飞区。

## 使用与导出

1. 建立“合成多层示例”，查看建筑、边墙、不同糙率、禁飞区、排水口、变化水源和两类人员。示例固定为 32×32，信号场是明确的合成示意。
2. 或选择当前生成地图与计算分辨率。使用原始地表类型的多数分类降采样，所有观测与位置同步到这一计算网格。当前地图不凭空添加人员或信号场。
3. 在固定环境地图点击编辑，把矩形或边墙加入草稿；再次“应用场景”才建立新的固定环境并重置时间／观测。可导入／导出场景配置 JSON。
4. 移动无人机，点击“观察当前视野”。推进洪水不会自动获取新观测。再次观察之前，已知地图保持旧值，信息年龄增加。
5. 查看另一架无人机或团队共享地图，检查各自知道的区域。下载 ZIP 留存全部状态。

ZIP 中含 `map_model.json`、`layers.npz`、`data_dictionary.json` 和 `events.json`。包含真实与已知地图、原始／已发现人员、地形与信号记录、逐格参数、水源过程、X/Z 动量、公共边通量、洪水起点水深和累计最大水深。未知掩码及采集时间一并保留，完整数据无需服务也能读。每次操作后原子更新 ZIP；服务内保留最多三次场景，历史 ZIP 不删除。服务重启后需要重新建立运行场景，已导出数据仍可分析。

```python
import numpy as np
from zipfile import ZipFile
from io import BytesIO
with ZipFile('map-result.zip') as archive:
    state = np.load(BytesIO(archive.read('layers.npz')), allow_pickle=False)
    true_depth = state['M_water.h']
    known_depth = state['agents.uav-1.M_obs.water_last']
    valid = state['agents.uav-1.M_obs.water_valid']
    observed_at = state['agents.uav-1.M_obs.t_water']
```

## 智能体接口与原有数据

`GET /api/maps/<场景id>/agent/<无人机id>` 返回已知信息和有效掩码，**不返回 `M_water`、完整高程或隐藏人员**。同一接口可读取 `team`。当前输出 16 个有名称的二维输入通道，所有数值有限；未知水深以零填入数值通道，但其有效通道为零，不能单独使用数值通道判断干燥。`?pool=2` 的示例水深池化只对有效记录求平均，另给出已知比例，避免把未知当零参与均值。

`legacy_exploration` 可提供原有通道数组 `[k,nz,nx]`，或包含 `legacy_channels`、`terrain_field/terrain_valid`、`signal_field/signal_valid`、探索掩码的对象。原始通道保留不被重写，前两通道用于派生曾探索记录；导入的地形与信号估计以零时刻先验记录，不能据此生成已知水深。原始 GMRF 推断器与九通道搜救训练网络不在本仓库中，本次完成数据承载与输入接口，没有伪造这些算法或已训练权重。既有网络接入时需要根据通道名调整输入并训练。

| 接口 | 功能 |
| --- | --- |
| `GET /api/maps/schema` | 数据字典 |
| `POST /api/maps` | 从 `current` 或 `demo` 建立场景 |
| `GET /api/maps/<id>` | 操作员全层快照，仅调试／评价 |
| `POST /api/maps/<id>/advance` | `seconds`，每次最多推进60秒 |
| `POST /api/maps/<id>/move` | `agent,x,z`，检查禁飞路径 |
| `POST /api/maps/<id>/observe` | `agent,valid`，当前视野采样 |
| `POST /api/maps/<id>/share` | `agent,target`，共享较新有效记录 |
| `GET /api/maps/<id>/agent/<agent>` | 执行用输入，不包含全图真值 |

创建场景的 `layers` 可导入同网格的 `z,n,solid,flight_allowed,source_id,drain_capacity,wall_x,wall_y,person_class,signal_field` 数组，或用 `patches` 编辑矩形。`initial_depth` 为可选的米制初始水深数组。`agents` 指定无人机编号、计算格 X/Z 和视野半径。使用当前地图时同时提交 `terrain_id`，避免误用已经变化的地图。实时场景从初始状态开始；如需基流预热，先设无雨并推进，或在原洪水工作台使用已有预热流程。

## 验证范围

运行 `python -m unittest discover -s tests -v`。多层检查覆盖墙面和建筑不漏水、变地形静水保持、逐格摩阻、事件时间对齐、排水限制和收支、观测隔离、有效零与未知、人员和水体共存、多机与过期共享、无效／遮挡观测、禁止倒退时间、禁飞整段路径、未知池化、原探索／估计导入和 ZIP 数据完整性。这些是物理不变量与接口检查，尚不等同于独立精度基准或网格收敛验证。PPT 的局部惯性求解器替代方案与 GMRF 算法复现不属于本次地图层实现。
