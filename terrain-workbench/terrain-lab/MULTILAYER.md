# 多层地图与洪水

打开 `maps.html`，统一查看固定环境与洪水过程。旧 `flood.html` 入口会进入同一工作台。页面不再创建无人机，也没有移动、观测、共享、探索或智能体输入体系。

## 地图层

所有数组共用 `[z,x]` 网格、原点和米制间距。

| 地图层 | 内容 |
| --- | --- |
| `M_base` | 高程 `z`、地表类型 `terrain_class`、逐格糙率 `n`、不透水建筑 `solid`、阻水边 `wall_x/wall_y`、水源编号与排水能力 |
| `M_water` | 实际水深 `h`、X/Z 速度 `u/v`、每格体积、累计最大水深、公共边输水通量 `qx/qy` 与水量收支 |
| `M_forcing` 外源来水 | 稳定入口编号、原始坐标、计算格权重、启用状态、时间流量过程、瞬时源率和每点累计来水 |
| 洪水过程 | 从零时刻到总时长的已计算状态序列，与固定环境使用同一网格 |

固定地图可以切换高程／等高线、地表类型、糙率、建筑与阻水边、水源与排水。水深、流速、累计最大水深同时显示，并随同一时间轴更新。

建筑是水深为零的不透水格；阻水边封闭公共面，两侧仍保留流体压力。雨水只计入非建筑格，尚未模拟屋顶雨水转排。排水能力为每格 m³/s，上限受可用水量限制。糙率参与 Manning 摩阻，地表类别是独立分类，不自动推断其糙率。

`source_id=-1` 表示无水源。其他编号对应 `hydrographs` 的递增 `[秒,总流量m³/s]` 序列，以分段常数执行；同编号多格平分总流量。求解器按变化时刻切分子步，不越过事件误用旧流量。日常河流基流与额外来水分别计入收支。`qx` 形状 `[nz,nx+1]`，`qy` 形状 `[nz+1,nx]`，单位 m²/s，是最终计算子步的实际公共边通量；`qy` 正方向为 +Z。

## 外源洪水与上游来水

生成完成时，服务从原始网格的河道类型与地面／水面高程识别河道和地图周边的连续交点，将元数据保存为该地形目录的 `river-inlets.json`。已有地图读取时也补全这份标注。生成页面和多层地图都显示交点；入口、出口与方向待确认分别标记。

交点方向依据附近向图内的水面或河床高差推断，不代表实测流向；平坦或无足够内侧河道的交点保持待确认，不默认注水。原始图上没有河流，或河流没有经过边界时，不会制造入口，可手动标注。

展开“外源洪水／上游来水”，选择推断河口或点击“在地图上选择入水点”。选点只确定位置，再点击添加才建立来水配置；可手填原始格 X/Z，不要求该处有河流。设置流量与开始／结束时刻，或启用自定义 `[秒,m³/s]` 序列。每条序列按分段常量执行，可模拟不同上游洪水过程。支持同时配置最多32个点，逐点启停、改流量和移除；应用或重新模拟后生效。

每个自动交点用原始边界几何生成稳定编号，改变计算分辨率不会重新编号。河口覆盖的原始河道格按比例映射到计算格，多格共享指定总流量；粗化不会把每格都当成一份完整流量。手动点保留原始整数坐标和配置编号。建筑内的有效注水点会被拒绝。

外源来水是**附加洪水输入**，与降雨、原有内部水源、指定常量来水、日常河流基流分别统计。基流预热不提前执行外源洪水过程，正式洪水的时间零点重新开始每点累计量。流量变化时刻与计算子步对齐，避免跨过开始／结束时刻多注水。图上紫色标记显示当前播放时刻的流量，来源及启用状态也保留在数据中。

当前实现通过入口计算格的体积源注水，源率为 `Q × 权重 / 格面积`，之后由浅水求解器运输；它没有额外指定上游水位或入流动量，不能等同于完整的流量—水位边界条件。

强化学习接入可直接使用配置中的 `external_inflows` 与 `M_forcing`：固定场景编号／原始位置，抽样或修改每点流量过程，重复运行同一地形；水情与外源参数分开存储。此处提供场景和数据接口，没有引入无人机或训练体系。

```json
{
  "external_inflows": [
    {"id":"manual-1","kind":"manual","x":128,"z":128,"enabled":true,
     "hydrograph":[[0,10],[30,100],[90,30],[120,0]]}
  ]
}
```

自动河口使用 `kind:"river"` 和当前 `GET /api/current` 的 `river_inlets.crossings` 编号，几何由服务端核对，不接受失效编号。完整JSON配置可导出和再次导入。当前显示水情JSON也含 `M_forcing` 的本轮已应用配置、所选时刻的每点流量／源率，以及最近实际帧的逐点累计量与对应时间；未应用草稿不会改写已计算结果。旧单点常量来水配置在页面导入／恢复时转换为独立外源点，不会再重复叠加原常量输入。

## 运行与播放

1. 默认读取当前生成地图；也可以选择32×32建筑与水源示例。
2. 设置模拟总时长、降雨及结束时间、入渗、初始水体、边界、日常基流与预热。展开指定来水可添加额外的常量体积源；点击地图选中原始来水坐标。
3. 点击“开始洪水模拟”，后台一次运行完整过程，无需反复点击推进。默认记录121个计算状态，可通过配置将 `flood.frames` 设为2—241。水动力子步仍由自适应CFL控制，记录间隔不是求解器步长。
4. 已计算时段自动连续播放；支持暂停、1/5/10/30/60倍速、回到起点与小数秒时间轴拖动。播放追上计算进度时等待新帧；取消后仍可查看已完成时段。
5. 播放按相邻实际计算帧线性平滑显示，界面标明“帧间平滑显示”。完整导出保留原始计算帧。当前显示JSON标明是否插值和来源时刻；水量收支显示最近的实际计算帧，避免把插值当作一次物理计算。
6. 固定环境编辑写入草稿，重新应用或模拟后生效并从零时刻开始。计算中不可修改本轮环境；可导入／导出地图场景JSON。

海岸只在生成器标识的海洋最外侧公共面连接固定水位外海，允许双向交换；其他边界只出流。无海岸不强行补海水。另可选择全部自由出流或封闭。日常基流使用原始河道连通段与最高有效水面附近的补给格，是合成参数；预热只使用基流和入渗，不提前执行洪水水源过程。预热达到时限而未稳定会明确显示，洪水零时刻保留预热水深与动量。

## 接口与导出

| 接口 | 功能 |
| --- | --- |
| `GET /api/maps/schema` | 物理地图与过程数据字典 |
| `POST /api/maps` | 建立 `current` 或 `demo` 场景；返回固定地图与初始水情 |
| `POST /api/maps/<id>/run` | 异步开始完整洪水过程，立即返回202 |
| `GET /api/maps/<id>/status` | 进度、已计算帧、预热结果与完整导出地址 |
| `POST /api/maps/<id>/cancel` | 取消计算，保留已完成时段与导出 |
| `GET /api/maps/<id>` | 场景初始图层与当前过程状态；不会读取正在变化的求解器数组 |

原 `advance/move/observe/share/agent` 接口已移除。页面刷新会恢复上一次洪水过程，地址中的场景编号也可以在同一服务中再次打开。服务保留最多三次地图场景、同时允许一个多层洪水计算；不会淘汰运行中的场景。历史文件留在磁盘，服务重启后需重新建立运行场景。创建和运行场景不修改 `current.json`。

配置的 `layers` 接收同网格 `z,n,solid,terrain_class,source_id,drain_capacity,wall_x,wall_y` 数组，或矩形 `patches`。`initial_depth` 可导入米制初始水深。当前地图必须携带当前 `terrain_id`。旧含无人机／探索的配置被明确拒绝。

ZIP 位于 `generated/maps-<id>/maps/map-result.zip`，包含：

- `map_model.json`：固定环境、最终真实水情、场景及水源／海岸／基流元数据、外源点与流量过程。
- `layers.npz`：固定地图、最终水深／速度／动量、公共面流量、初始与累计最大水深、基流率，以及 `M_forcing.inlet_count` 和 `M_forcing.external_rate_m_s`。
- `process.json` 与 `frame-*.f32`：计算时刻、每帧实际水量收支、`external_inflow_by_id_m3` 逐点累计量以及 `depth,u,v,maximum_depth` 四平面的 little-endian float32 数据。
- `data_dictionary.json`：各数组的单位、形状与显示插值说明。

取消时完整帧序列止于最后完成时刻；最终NPZ还可保留取消时更晚的计算子步状态，其时间在 `map_model.json` 中。无已完成帧的预热取消也可导出当前状态。

## 验证与限制

运行 `python -m unittest discover -s tests`、`node tests/test_map_playback.mjs` 与 `node tests/test_inflow_controls.mjs`。覆盖建筑／墙面不漏水、静水保持、糙率、排水、事件对齐、整段帧生成、预热隔离、取消保留、导出、当前地形同网格，以及小数时刻播放与插值。外源检查覆盖入口／出口推断、无河流／内陆河道／平坦交点、角点去重、跨分辨率总流量守恒、多点事件计量、预热隔离、失效编号、导出与重放。水动力继续使用完整二维浅水方程的一阶有限体积方法。这些验证不等同于真实洪水校准或独立精度基准；粗网格与一阶数值扩散仍会影响狭窄河道和淹没边界。

河口候选支持勾选多个交点批量添加；待确认方向不限制来水。列表显示已配置、已启用点数，修改后需应用或重新模拟。

海域分类先保留原始生成字段，再生成独立的水体分类字段：原始 river 标签只有在河道分区明确为 None、水面不高于海平面且被淹没、与已有 ocean 单元四邻接连通时才恢复为 ocean。河床、河岸等有河道分区的低海拔河流和孤立水体保持原分类。修正字段用于地图地表、河口识别、日常基流和海边界，原始数据不被改写。
