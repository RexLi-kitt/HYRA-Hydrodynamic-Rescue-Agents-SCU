# 地形实验台

“多层地图与洪水”（`maps.html`）统一固定环境编辑和整段洪水计算。高程、地物、糙率、水源、排水与水情使用统一格宽；页面可选原始、2倍或4倍格宽，河流、湖泊、湿地和海洋保持相同计算格宽。支持连续播放、暂停、倍速和时间轴拖动。[使用与数据字典](MULTILAYER.md)说明地图层、原始网格、运行和导出。

运行 `python3 launcher.py`，或者双击 macOS 的 `启动页面.command`，在浏览器打开 <http://127.0.0.1:8766/>。

内置示例无需 Java 即可查看。生成新地图需要 Java 21，首次构建需要联网下载依赖。完整的安装、生成和矩阵导出说明见 [工作台说明](../README.md)。

生成器会先检查 Java 21 JDK，优先使用 `../freeterraforged-reproduction/.runtime/java/` 内解压的 JDK，再检查 `JAVA_HOME` 和 PATH。Java 24 等其他版本会立即给出提示。构建下载会使用已有系统 HTTP/HTTPS 代理；需要认证的代理请自行配置 Java。Gradle 下载使用官方直连地址并校验固定 SHA-256。

网页导出使用 Loom 的 CI 模式，跳过 IDE 依赖源码下载与转换；运行依赖与地形算法照常构建。Windows 使用 Java 参数文件传递完整类路径，并按系统编码写入，支持中文目录，避免启动器压缩类路径后找不到游戏文件或重复加载 Mixin。

首次下载和构建时显示阶段说明，进入地形计算后显示实际进度。首次依赖源码转换可能持续数分钟。可随时“取消生成”或“查看生成记录”；连续 10 分钟没有新日志、总计超过 30 分钟会自动停止并保留原地图。失败和取消后仍可查看本次记录。

“水系丰富”与“原始参数”按钮载入参数；调整后点击“生成地图”应用。快速预览提供高程与河网；完整地表进一步提供实际地面方块、水面与群系。“图片预览”打开当前图层的图片。

“目标地形”可选择稠密水网、高山、平原或自由调整。三个典型模式控制地貌权重、起伏及河网参数，并保留用户的种子、地图大小和生成方式。同一种子在不同模式下产生不同地图；同一种子、模式和请求坐标的搜索顺序可复现。修改地形滑块会回到自由调整；修改种子、范围或生成方式保留目标模式。

典型模式最多检查请求坐标附近九个区域，先检查高程和河网，再为通过的区域生成完整地表。成功结果记录实际坐标，完整地表还会重新检查；找不到符合标准的区域、取消或超时均保留原地图，不承诺每个种子和范围都能找到目标。自由调整不移动区域，也不设验收条件。一次任务的总时限仍为 30 分钟。

验收规则 v3（当前一个方块单位对应一米）：水网要求陆地 ≥55%、有水河道的中心线长度密度 ≥0.8 km/km²、河道覆盖至少 10/16 个分区且穿越地图边界至少三处、陆地 P95−P5 高差 ≤80 m。中心线由有水河道栅格细化后估计，长度按实际采样间距换算，面积为陆地与内陆水体面积。水面占比仍展示，但不作为硬门槛：细河道在大范围地图中可能水面占比低，却有广泛河网。粗采样仍可能漏掉小于采样间距的支流。高山要求陆地 ≥70%、原生山地占陆地 ≥25%、陆地 P95−P5 高差 ≥80 m、P90 高程 ≥140 m；平原要求陆地 ≥70%、陆地 P95−P5 高差 ≤45 m、P90 坡度 ≤0.15。海洋与只有湖泊的场景不算水网。规则定义工作台的合成地形类型，不代表真实流域标定；水网检查验证覆盖和边界交点，不保证天然支流的拓扑结构。

低起伏模式使用原生 MULTI 大陆算法，并降低独立山脉层的幅度、统一基础高程；高山保留 UPLIFT 大陆算法。只使用原生成器配置，不修改保存的上游源码或生成后的高程。

每次搜索保存 `terrain-search.json`，成功后保存 `terrain-profile.json`（指标、模式版本、种子、请求与实际坐标、检查次数）；每个候选的生成记录独立保存，失败报告列出未达标项。相同种子、模式、范围和坐标会重复相同搜索；需要换候选时应修改种子或区域起点。网页显示检查结果与实际区域坐标，多层洪水过程元数据也保留模式与验收报告。

相同种子与原生生成预设的历史候选可复用。只复用网格形状、坐标、采样间距、上游版本、无高度裁剪策略及字段长度匹配的原生预览；每次都使用当前验收规则重新检查，不沿用旧的通过/失败结论。URL 标注和实际地表不从预览缓存复制，完整地表仍按请求生成。报告中的 `reused_preview` 记录来源。

运行数据、最新地图指针、生成世界与构建缓存均被 Git 忽略。无运行数据时默认显示 `example/raw`。

洪水过程已融入多层地图，旧 `flood.html` 地址自动进入 `maps.html`。支持降雨、指定来水、变化水源、入渗、日常基流预热和海平面双向交换，整段异步计算并连续播放。完整过程下载为ZIP，当前显示水情可导出JSON与PNG。需要上一级 `requirements.txt` 中的NumPy。

外源洪水支持自动标注河道入图处和手动选点，逐点配置上游流量过程、启停和时间窗口。与日常基流分别计量，入口编号、原始位置、计算格映射与累计入水保留在 `M_forcing`，方便后续场景抽样与训练接入。

## 洪水计算速度

页面默认选择4倍原始格宽用于快速预览；后端和缺少 `grid_factor` 的旧配置保持原始格宽。1米原图选4倍后，512×512变为128×128计算格。只改变水平计算网格，不缩放高程、时间、降雨或总流量。高程与初始水深按面积平均，初始总水量守恒；细河道会被平均，建筑取并集、排水容量相加、墙投到最近的大格边。需保留窄河道细节时选原始或2倍格宽。

可选编译加速使用同一套空间重构、通量、RK推进和CFL公式，不启用 fast-math。安装 `terrain-workbench/requirements-acceleration.txt` 后自动使用；也识别本目录 `.runtime/acceleration-packages` 中的项目本地安装。没有可用Numba时保留NumPy实现。`HYRA_FLOOD_BACKEND=numpy` 可强制参考实现，`numba` 可强制编译实现并暴露依赖错误；导出数值设置记录 `compute_backend`。兼容范围见[Numba官方安装文档](https://numba.readthedocs.io/en/stable/user/installing.html)。

首次编译有一次性等待，之后复用磁盘缓存。基流预热与洪水推进期间至少每完成约1秒墙钟计算就更新一次状态，展示模拟时间和已算步数，不再等待整个预热窗口或输出帧间隔才报告。

当前地图对照可用 `benchmarks/benchmark_acceleration.py` 复跑；结果仅反映对应地图、参数和短时运行，不保证整个1500秒过程保持相同速度。

页面按场景、来水、地物、高级分组，结果默认单张主地图，支持四图对比。河口默认根据附近河道截面拟合切线动量方向，也可选垂直边界或自定义方位角；方向同时影响X/Z动量，指定总流量保持不变。切线是几何推断，数据不足时回退法向。已有过程保留原结果，修改方向后需重新模拟。
