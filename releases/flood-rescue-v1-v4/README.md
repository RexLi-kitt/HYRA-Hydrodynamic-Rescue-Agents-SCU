# HyRA 四条洪水搜救实验线

本仓库将我方四条独立实验线整理为 V1–V4 发布编号，每个子目录可独立安装和上传。编号用于组织发布，不沿用外部团队 Word 的版本归属。

| 目录 | 场景 | 核心方法 | 自身协议下的代表结果 |
|---|---|---|---|
|[V1](V1/README.md)|20 人固定、25 米扇形视野|Gaps 多步协同搜索与施救规划|93.70%，同图原 R2 为 82.19%|
|[V2](V2/README.md)|40 人动态落水与个人期限|GRU 区域需求预测，对照区域 GMRF|60 米 T0 98.93%；40 米 T0 91.33%、TG 92.11%|
|[V3](V3/README.md)|落水、浅滩、村落三类合成险情|冻结 T0/TG＋报警＋K1|T 82.19%，H 75.83%，G 68.11%|
|[V4](V4/README.md)|逐秒三波落水、180 秒期限|GRU 当前需求与 60 秒输运|M0 98.72%，M1 98.77%，较强纯规划 90.00%|

四版环境协议不同，表格用于定位实验。完成率应在同版共同场景中配对比较。

## 从哪里开始

1. 只发布一条实验线时，进入对应 V1/V2/V3/V4 目录，按照该目录 README 安装和运行。
2. 发布四版合集时，在本目录初始化 Git 仓库，四个子目录保留各自的源码、模型、结果及许可。
3. `results/` 是已完成实验的原始归档，`generated/` 是读者本机运行输出，后者由 .gitignore 排除。

V1 的 Python 依赖仅为 NumPy，并需要 Node.js。V2–V4 使用 NumPy、SciPy、PyTorch。V1 没有新增 DQN 训练；V2/V4 随包附有冻结监督学习权重，V3 复用 V2 权重。

## 结果边界

- V1 未达到原定 95%+ 目标。
- V2 的小视野与大视野分表呈现，GMRF 增量按同场比较。
- V3 的 GMRF 迁移结果为负，失败记录完整保留。
- V4 达到较高完成率，但对纯规划的提升为 8.77 个百分点，未达到 15 个百分点；60 秒前推相对 M0 的额外增益尚未证实。

整理后每个版本均重新完成一个真实水场布局的回放或重新决策核验。完整批次没有在本轮重新运行，具体范围见各版 VERIFICATION.md。

## 上传

在 GitHub 创建空仓库，将 `<仓库地址>` 换成自己的地址。

```powershell
git init
git add .
git commit -m "Publish four HyRA flood rescue experiment branches"
git branch -M main
git remote add origin <仓库地址>
git push -u origin main
```
