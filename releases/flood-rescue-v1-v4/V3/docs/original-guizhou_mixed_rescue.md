# 贵州山区三类险情的合成搜救实验

|案例资料|引用的事实|用于实验的设定|
|---|---|---|
|[央广网，2026 年平塘基哈村](https://gz.cnr.cn/hezuo/20260521/t20260521_527629794.shtml)|一名村民被洪水冲走后困在河中树枝上|16 人进入河段，按水场逐秒平流，与 12 个预先布置的障碍相交可挂靠|
|[绥阳消防救援报道，2024 年宽阔河](https://szb.fzshb.cn/fzshb/20240530/04.pdf)|8 人设定所借鉴的实际事件为 6 名露营者被困，消防使用无人机侦察|浅滩设 8 个固定人员目标，第 30 秒均需投放|
|[人民网，2026 年麻江县谷硐镇](https://gz.people.com.cn/n2/2026/0519/c222152-41585057.html)|多个低洼处有人被困，消防在下游回流湾发现房顶被困者|两个近河固定点，各 8 人，第 60 秒起需投放|

四机、单一合成河谷、人员配比、40 米视野、时间窗、报警精度、房顶位置和 300 秒任务均为模拟设置。使用原生水动力第 900–1200 秒的帧。原图为闭边界入流水场；静态名义下游队列沿地图河谷中心线从第 97 行入流端向域内延伸，最多 3 个区域。这表达洪水扩展方向的粗略线索，实际局部速度来自求解器。固定点抽样在近岸带，屋顶以平面坐标表示。没有复原真实贵州河床、流向或人员轨迹。

每个报警覆盖四个相邻的 100 米区，区内未扫比例按此次报警后的实测时间戳核算。多条报警重叠取最大值，H 排序见 study.py。原规划器先执行人员分配，空闲机才受新的搜索策略控制。到期当秒可完成最后一秒的投放。G 的比较对象 T 有相同的序列观测、候选落点和已知报警，两者来自既有独立训练的冻结权重。

从 uav-workbench 根目录运行 PowerShell：

```powershell
# 使用本仓库 requirements.txt 创建独立环境
$env:OPENBLAS_NUM_THREADS='1'
$env:OMP_NUM_THREADS='1'
python -m guizhou_mixed_rescue
python -m guizhou_mixed_rescue.analysis.audit
```

生成目录为 `generated/guizhou-mixed-rescue-v1`。入口按开发核验、封存、100 张地图生成、200 个布局、报告执行。重复运行核对封存并复用完整的原子写入布局文件。开发父图 31001–31006 各四个布局，独立父图 184001–184100，各两个布局；布置随机种子由 [20261104, 父图, 布局] 确定。H 每布局一次。分支仅用于诊断，不计入 1,400 场。G 的运行计时包含试算 T，不宜直接与 T 的运行耗时比较。

`person-pairs.csv` 每个 id/found/saved 差值按 G 减 T，同种子同布局。`people.csv` 保留未发生的时间为 -1、发现时剩余时间未定义则留空。`strata.csv` 用完整潜在轨迹划分落水者，与提前获救无关。`first-branches.csv` 列两个首步及以后恢复 G 的逐人增减。JSON 回放含每 5 秒位置和提交动作，附带的 HTML 支持逐秒浏览同图两支。报警、障碍与潜在轨迹摘要在 alarms.csv、development.json、cases 内，原生地图哈希在 maps.json。
