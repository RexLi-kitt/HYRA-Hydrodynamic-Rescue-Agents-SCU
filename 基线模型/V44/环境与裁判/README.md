# HYRA 搜救环境与裁判 · 20261106.1

本包用于在固定的 64 人、4 机、720 秒个人窗口、2400 秒总时长、1 米投放半径下接入自己的算法。视野为 20 米前向 180° 扇形，每 5 秒观测和决策一次。你实现选动作和分派目标，环境负责水情、人员自然轨迹、碰撞、观测、投放与记分。正式任务入口为 `run.py` 调用的 `DeliveryMission`。文件名中的 V8、V10 等是来源批次；本次可分发版本统一为 **20261106.1**。具体来源、原文件 SHA-256、哪些文件逐字节复制、哪些函数做了独立封装，见 `VERSION.json`。包内清单为 `SHA256.json`。

## 1　先验证，再写算法

使用 **CPython 3.12.14、NumPy 2.3.5**。运行时只依赖 NumPy 和 Python 标准库，CPU 即可。进入解压后的 SDK 目录，在 Windows PowerShell 运行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py verify
```

Linux/macOS 可用同版本 Python 创建环境，并用 `.venv/bin/python` 执行下列命令。本版本实际验证平台为 Windows x64。注意核对 `python --version` 的补丁号。离线环境可使用已经安装的相同依赖。

`verify` 从原研究运行环境录下的固定动作与分派开始，检查样例所有决策时刻及最后一帧的观测指纹、64 人逐人送达秒和全部指标，并运行碰撞等边界用例。三场对拍由同一参考规划器生成：普通洪水 **58/64**、持续高水 **29/64**、反复干湿 **27/64**，每场 480 步。你的新算法不必得到这些送达数；相同输入与相同动作记录才应该逐步一致。Windows 之外出现浮点指纹差异时，请保留报错的场景、步号、Python/NumPy 版本；不要调宽裁判误差来消除差异。

## 2　你的算法只需提供一个工厂和一个方法

复制 `example_policy.py` 为 `my_policy.py`。文件内提供 `make_policy()`，返回一个含 `act(obs)` 的对象。每份人员名单开始前都会创建新对象。若算法需要随机数，在算法内显式固定并登记随机种子。每步返回 `(actions, targets)`，两个长度均为 4 的整数数组，依次对应四架机。人员编号 0–63，−1 表示无目标。

| 动作 | 水平坐标方向或行为 |
|---|---|
| 0、1 | +y、−y |
| 2、3 | −x、+x |
| 4、5 | (−x,+y)、(−x,−y) |
| 6、7 | (+x,+y)、(+x,−y) |
| 8 | 无可见指定目标时悬停；指定当前团队可见人员时，用步首观测速度跟随并尝试投放。 |

斜向已归一化。完整平移为 50 米。平移时若指定当前可见目标，进入 0.5 米内圈的飞行射线可提前停下；接近本身不计投放。建议不同飞机分派不同目标。裁判使用联合动作同步结算，算法不能根据同一步其他飞机尚未结算的结果修改自己的动作。

```powershell
python run.py eval --agent my_policy.py:make_policy --out my-run.json --save-actions
python run.py replay --result my-run.json
python run.py regenerate
```

第一条在三张样例图上运行，保存逐场、逐人结果和动作带。第二条只重放动作与目标编号，不调用策略，核对所有场次的指标与逐人秒数。第三条从水场、候选起点、拦阻物和已冻结的种子重新生成人员，逐数组比对首次落水、2401 帧位置、可用性和步首速度。运行全量面板时，在这三条命令上加相同的 `--panel` 参数。建议使用新的输出文件名。

## 3　可见信息及其边界

| 字段 | 内容 |
|---|---|
| `t, pos, heading` | 任务秒，四机连续位置及单位航向。 |
| `last, measured` | 100×100 格心的最近观测秒，−1 为未观测；三层最近观测的 h、u、v，未观测区域初值为零，以 last 判断是否有证据。 |
| `observed_cells, new_cells` | 本时刻全队看到的格心、其中第一次看到的格心。扁平索引 = 行×100+列。 |
| `visible, seen_at, seen_xy, seen_v` | 全队此刻可见人员、最近看到的秒／坐标／速度，seen_at 为 −1 表示从未看到。投放步首须为当前可见。 |
| `active, owner` | 已知目标最近观测到的服务状态，以及待续投放的机号（−1 表示无机续投）。视野外不会遥报未观测的出界或到期。 |

向策略提供的数组为独立、只读副本。部署算法只可使用上述信息及其历史；禁止读取样例或面板中的全水场、人员真值、地图标签、种子、动作带或未来帧来决策。单进程 Python 接口用于本地合作复现，不提供反作弊隔离。样例与可选 80 场均为开发材料，封存盲测图不会随包分发。

## 4　发生判定分歧时查这里

| 项目 | 生效文件及行为 |
|---|---|
| 碰撞与边界 | `engine/supply.py` 中的 `raw_conflicts` 和 `intentions`。将整秒及各机精确停下的时刻都作为折点，对每段求最近距离。代码判断小于 5−10⁻⁸ 米时为冲突。冲突机从步首位置停止整步，重新检查，直到停止不会引出新冲突。ACC 只累计原始意图中的无序机对数一次；连锁停止会影响动作但不会追加到原始机对数。边界事件独立计数。 |
| 感知与跟随 | `engine/supply.py` 的 `sample_cells`、`Supply.sample/observation`，以及 `engine/delivery.py` 的 `step`。在 0 秒及每个 5 秒边界按前半圆采样；平移更新朝向，悬停／跟随保持航向。跟随整步使用步首速度，上限 10 米/秒。 |
| 首次落水、漂流和复漂 | `engine/scenario_io.py` 的 `regenerate`、`engine/motion.py` 的 `shape/simulate`、`engine/long_environment.py` 的 `sample_water`、`Env.move_people/refloat_draw`。保留原实现每秒推进、首次线段碰障、浅水搁浅、按人按秒复漂和出界规则。复漂随机数不依赖策略调用次数。 |
| 投放 | `engine/delivery.py` 与 `engine/judge.py`。每个 5 秒步在首尾等六个整秒节点检验距离 ≤1+10⁻⁹ 米。必须同机、同人、连续两个有效步。超距、换机、中断、机间冲突或人员不可用会中断。截止秒恰好完成有效。投放成功计一次。 |
| 水场读取 | `engine/scenario_io.py:load_water`。保留原 float32 位值；普通图形状为 (481,3,100,100)，压力图压缩表示为 (481,3)，读取时广播。层顺序 h（水深，米）、u/v（水平速度分量，米/秒）；索引为 [帧,层,y,x]。格心在 10×列+5、10×行+5 米处。 |
| 指标与终止 | `engine/mission_env.py:MissionSupply.metrics` 和 `run.py:aggregate`。送达分母为全体 64 人，跨场按人次累加。ST、FRT、CRT 的单位为 5 秒步；未发生的 FRT/CRT 为 null，汇总给有效场数。ACC 为原始冲突机对数除以实际步数。全员送达且全部格心已探索才可提前结束。即使全员已送达，若覆盖未完，仍可能记 timeout。 |
| 浮点判定与回归 | `engine/contract_checks.py` 包含扇形边缘、碰撞与连锁停止、跟随与中断、1 米边界、恰在截止秒完成、岸边复漂及实体拦阻。位置不要预先取整或换算为格。 |

`run.py` 在首次导入裁判前锁定半径为 1 米。请始终用该入口；保留的父类含早期实验默认值，直接实例化旧父类会调用其他规则。人员生成中保留的历史 Config 窗口字段仅随运动对象传递；本次投放截止由生效的 MissionSupply 用 720 秒计算。算法若想改变决策频率，须另行登记，不能与本版混评。

## 5　复现 80 场开发面板

另一个压缩包 `HYRA-dev80-20261106.1.zip` 含 24 张普通图、8 对压力父图（对应 16 张压力图），每张图两份固定名单，共 80 场、5120 人次。解压在 SDK 的同级目录即可：

```powershell
python run.py eval --panel ../HYRA-dev80-20261106.1 --agent my_policy.py:make_policy --out my-80.json --save-actions
python run.py replay --panel ../HYRA-dev80-20261106.1 --result my-80.json
python compare.py my-80.json reference-v16-dev80.json
```

最后一条使用包内附带的原实验 V16 强纯规划对照，80 场共送达 3662/5120 人次，可直接和你的结果配对。也可以传入另一策略生成的结果。比较要求相同版本、相同面板校验值、相同逐场名单，报告送达率差（百分点）、相对收益，以及按普通图／压力父图分层的 20000 次配对重采样区间。三场样例用于对拍，统计比较请使用完整开发面板或另行预登记的独立数据。包内水场为原实验的冻结输入，运行团队算法无需重跑水动力求解器。
